# Command-local Linux process supervision

Each Linux target runs under a dedicated, single-threaded supervisor launched through a private entry point in the existing CLI executable. The supervisor becomes a child subreaper before starting the target, continuously reaps its children, and kills and reaps remaining descendants when its control channel closes. This ownership survives descendants creating new sessions and avoids a global subreaper competing with Tokio's child waiters. The supervisor has a separate process group so foreground interrupts reach the CLI, which closes the control channel to request cleanup.

A private Unix socket carries the target request and original root exit status; targets cannot inherit that socket. Captured stdout and stderr remain separate from the protocol. Root exit closes the supervisor's output handles, preserving stream draining for descendants that still hold those pipes. Successful completion also closes the control channel, so background children that redirected their output are cleaned up. Protocol failures use the same bounded cleanup path. The CLI reaps cancelled supervisors before returning.

This adds one process and a small polling interval per target and requires Linux procfs. It provides process-lifecycle ownership, not an execution sandbox. Windows continues to use a kill-on-close job, and other Unix platforms use process-group cleanup. Uninterruptible kernel waits can exceed the cleanup deadline and are reported as cleanup failures.
